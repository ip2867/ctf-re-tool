## 1.1 结构异常检测

`elf_anomaly` 一次报出 6 类异常：

![elf_anomaly](images/qwb2026/t1-1-anomaly.png)

关键三条：

1. **`segment-slack-data`**：`0x1988`（517B）和 `0x7396`（1741B）落在 LOAD 段的**页尾缝隙**里。

## 1.5 算法结构（两段 30 轮 ARX）

第一段：`S[2]=K0, S[3]=K1`，递推 30 轮得到 `S[4..33]`，**只依赖 K0/K1，与输入无关**：

```
t = rol((S[i+1] | S[i]) + (S[i+1] & S[i]), 13)
u = ror(S[i], 7)
S[i+2] = ((t | u) - (t & u)) ^ r11       ; r11 每轮 += 0x9e3779b97f4a7c15
```

第二段：`r8 = x0^K0, r9 = x1^K1`，30 轮：

```
t1 = rol(r9 + S[i+2], 13)
t2 = rol(r9, 29)
t4 = rol(r9, 47)
r10 = (t1 ^ t2) + t4
r8, r9 = r9, r8 ^ r10
```

> 注意 `(a|b)+(a&b) == a+b` 和 `(a|b)-(a&b) == a^b` 都是恒等式，
> 所以那堆混淆写法等价于「加 / 异或」，是纯 ARX，可逆。

# 附录 C · 六条容易踩的陷阱

以下六点都是复现过程中真实遇到、且会直接导致结论错误的地方，整理出来供后续参考。

1. **页尾 slack 的地址 IDA 加载不了** —— 这不是 IDA 的问题，而是那段代码不在任何 section 里。
   `elf_anomaly` 报 `segment-slack-data` 就是在提示这件事：内核按整页映射，
   `p_filesz` 之外的部分依然可读可执行，但静态工具按 section 解析时会跳过。

2. **同一文件里明文与密文可以共存** —— `0x765e`（`/proc/self/status`）是明文，
   而 `0x76a6`（目标值）是密文。只有后者被加密，从静态偏移直接读会得到"部分正确"的废数据。
   必须用 gdb 读运行时内存才能拿到真值。

3. **自洽不等于正确** —— 若 `K0`/`K1` 取错，逆推出的 flag 会全错，
   但正向回代仍然能通过，因为回代用的是同一套错误常量。
   **必须与官方题解或原程序输出对拍**，不能只看自身是否自洽。

4. **断点位置差一条指令就读错** —— fw_b 的断点要在 `0x103fc`（`jal 0x10818` 返回之后），
   而不是 `0x103f8`（调用之前）。后者读到的还是 `.selfhash` 原值。

5. **浮点表的参数是索引不是偏移** —— license 的 `decode(0x22a, 24)` 中，
   `0x22a` 是表索引而非字节偏移；解码函数是 `asin` 而非 `acos`。
   按字节偏移 + `acos` 计算会得到 0/24 匹配，从而误判"浮点表不是 flag 来源"。

6. **IDA MCP 的 `py_eval` 会被模态框阻塞** —— 若通过模拟鼠标触发了非法的
   "Jump to address" 弹窗，MCP 调用会卡住不返回。
   正确做法是全程使用 `py_eval` + `ida_kernwin.jumpto()`，不要模拟鼠标操作。
