## 2. 项目是什么 `[已验证]`

一个 **CTF 逆向 AI 解题工作台**。核心设计原则：

> **AI 是解题主体，工具提供能力。**
> 不是把功能堆在一起，而是让 AI 在解题过程中真正调用工具、识别算法、验证结论。

关键机制：

| 机制 | 作用 | 实现位置 |
|---|---|---|
| Tool-Use 循环 | AI 自主调用工具反复推进，最多 25 轮 | `src/js/app.js` |
| 四阶段提示词 | ①收集 → ②定位算法 → ③脚本本地验证 → ④结论 | `src/js/app.js` |
| 本地验证闭环 | `[VERIFY]` 契约 → 生成 Python 复现 → 标 ✅/⚠️ | `src/js/app.js` |
| 知识库检索 | `wiki_search` / `wiki_read` 按关键词加权检索 | `electron/main.js` |

| 动态调试 | `ida_dbg` 系列工具，本地 PE + Kali 远程 ELF | `electron/ida-dbg.js` |
| 长任务可靠性 | 上下文压缩、死循环拦截、失败环 | `electron/agent-runtime.js` |

**技术栈**：Electron 35 + 原生 JS（无框架）+ Anthropic `/v1/messages` 协议 + MCP 客户端。`[已验证]`

## 5. 关键设计决策（不要轻易推翻）

### 5.1 动态调试是"取证"不是"探索" `[已验证]`

`src/js/app.js` 里的四条入场条件：
1. 有函数清单
2. 候选函数说得清职责（读输入 / 做变换 / 比对 / 解壳）
3. **写得出调试假设**：断点地址 + 读哪个表达式 + 期望值 + 判定方式
4. 有办法把流程逼到那里

写不出第 3 条 = 静态没读够，回反编译。

**为什么**：无假设直接 `start` 会在系统 DLL 和消息循环里漫游几十轮，零信息。

### 5.2 进程状态语义（三个实现坑，别再踩） `[已验证]`

```
get_process_state() 返回值：
  -1 = 已暂停（可单步 / run_to / 写内存）
   0 = 无进程
   1 = 运行中（单步必然失败）
   2 = 已退出
```

三个历史根因（都已修，别改回去）：

1. **语义判反**：曾把 `1` 当暂停等、把 `-1` 当无状态 → 所有单步"失败"。
2. **`continue` / `run_to` 是异步投递**：插件返回的 IP 是投递前旧值，必须轮询 `waitDbgStop()` 到真正停下。GUI 程序进消息循环后 STATE 恒为 1，这是正常状态而非错误。
3. **`start_process("")` 在路径为空时返回 0（启动被取消）**：以前"能用"是因为进程选项残留了上次的目标路径。做过一次远程调试后残留变成 Linux 路径，本地启动就稳定失败——**这才是"本地调试时好时坏"的真因，与 ScyllaHide 无关**。现在 `buildStartPrelude` 会回落到 `idaapi.get_input_file_path()`。

### 5.3 远程 ELF 与本地 PE 的三处差异 `[已验证]`

| | 本地 win32 | 远程 linux |
|---|---|---|
| start 后 | 自动停在入口 | **不停**，需主动 `suspend` |
| 断点地址 | 静态地址即可 | PIE 必须用**重定位后**地址 |
| 断点 API | 均可 | `dbg_add_bp` 恒 False，必须 `idaapi.add_bpt` |

远程用 Kali 上 IDA 自带 `dbgsrv/linux_server`（**不是 gdbserver**），调试器名 `"linux"`。

### 5.4 知识库"写了但搜不到"是最大陷阱 `[已验证]`

失败模式：页面存在、检索函数正常，但自动预取选词选不到 → AI 永远看不到。

已修：`src/js/app.js` 的 `FEATURES` 有动态调试结构特征（VirtualProtect / IsDebuggerPresent / DialogBoxParam / GetTickCount），`POOL` 有中英文检索词，提示词的 `METHOD_PAGES` 显式点名 7 篇方法论。

**回归保护**：`tests/test_knowledge_reachability.js` 模拟 `prefetchKnowledge` 选词 + 打分，验证 5 类特征都排第 1、普通题不误命中。

## 7. 失败过的路（不要重复）

### 7.1 动态调试 `[已验证]`

| 尝试 | 结果 | 真实原因 |
|---|---|---|
| 用 `gdbserver` 做远程 | 连上但调试器不接管 | 必须用 IDA 的 `linux_server` |
| 禁用 ScyllaHide 后单步成功 | 误判为根因 | 真正原因是状态语义判反 |
| `load_debugger("linux")` 返回 False | 以为不支持 | **连到了仍加载 PE 的旧 IDA 实例** |
| 连上后立刻 `Closing connection` | 以为调试器有问题 | 目标自己退出了（plutochat 连不上服务端） |
| 断点设了不命中 | 以为断点 API 有问题 | 目标在调试器下完断点前就跑过了 / PIE 用了静态地址 |

### 7.2 环境坑 `[已验证]`

- **`taskkill` 杀不掉挂满插件的 IDA** → 用 `powershell -Command "Stop-Process -Name ida -Force"`
- **`tasklist` 在本机报"无效类"** → 改用 PowerShell `Get-Process`
- **Kali shell 是 zsh**：未匹配 glob 会报 `no matches found` 并中止整条命令 → 通配符放 `sh -c '...'` 里

### 7.3 两个未解题目 `[已验证]`

- **CrackMe2**：已通过公开题解 + 独立 BFS 交叉验证得到 30 字节 serial（见 `solved-challenges.json`），**不是 flag{} 形态**，平台 flag 值未知。
- **cnbragon**：轮函数 oracle 稳定可用，但 `0x4101f0` 是 base64-style 解码器，**寄存器+栈混合的参数约定没推定**，35 字符输入无法映射到 16 字节 key 材料。已按用户指示跳过（见 `skipped-challenges.json`）。

## 10. 发布流程（两个站，别漏）

### 10.1 工具发布

```bat
cd /d "C:\Users\Administrator\Desktop\工具\ctf-tool-v2"
npm run build:exe
REM 产物：dist\CTF-RE-TOOL.exe（约 74 MB）
```

**已知问题**：`dist\win-unpacked\resources\app.asar` 会被 Windows Defender 实时防护锁住，导致 `EBUSY` 删除失败。
**绕法**：输出到新目录
```bat
npx electron-builder --win portable --config.directories.output=dist-180
```

然后：
1. 算 SHA256 → 更新 `README.md` 的校验值
2. 拷 exe 到发布仓（被 `.gitignore` 排除，只随 Release 分发）
3. `git push` 发布仓
4. 用 GitHub API 创建 Release 并上传 exe（`gh` CLI 未安装；token 在 git credential 里，可用 `git credential fill` 取）

### 10.2 Blog 发布（两个目标，很容易漏）

```bat
cd /d E:\blog\hugo_extended_0.153.2_windows-amd64\MyBlog
hugo.exe --minify

REM 目标 1：Firebase
firebase deploy --only hosting --non-interactive --debug

REM 目标 2：GitHub Pages（public/ 是独立 git 仓库！）
cd public
git add -A
git commit -m "post: xxx"
git push origin main
```

**坑（全部实测）**：
- `public/` 目录**自带 `.git`**，是独立仓库（remote = `ip2867.github.io`），不是普通子目录
- 文章 `date` 必须早于当前时间，否则 Hugo 当"未来文章"跳过不构建
- Firebase 需 `--debug` 参数绕过 `ProxyAgent` 循环引用 bug（`firebase-tools` 15.1.0 + Node 24）
- 代理：`github.com` 直连不通，git 需 `-c http.proxy=http://127.0.0.1:7890`
- Firebase Spark 计划禁止托管 exe/apk/py，靠 `firebase.json` 的 `ignore` 排除
- 启动脚本 `启动.bat` 必须纯 ASCII——UTF-8 中文在 cmd 默认 GBK 代码页下会导致命令执行失败
