# 加密算法识别与还原

## 特征速查表

| 特征 | 算法 | 还原要点 |
|---|---|---|
| `0x9E3779B9` | TEA/XTEA/XXTEA | 看 32 轮循环 + 移位数：`<<4 >>5`=TEA；`<<4 >>5`+key数组轮换=XTEA；按块遍历+奇偶配对=XXTEA |
| S盒 `63 7C 77 7B F2 6B 6F C5` | AES | 找密钥扩展(KeyExpansion)确认 key 长度 16/24/32；ECB/CBC 看 IV |
| S盒 `D6 90 E9 FE CC E1 3D B7` | SM4 | 32轮非平衡Feistel结构+线性变换L；gmssl 库直接解（ECB/CBC） |
| 常量 `a3b1bac6 56aa3350 677d9197 b27022dc`（FK） | SM4（铁证） | 系统参数 FK 出现在二进制即为 SM4；轮常数 CK 表同理 |
| 摘要 IV 以 `0x7380166f` 开头 + 64 轮 | SM3 | **哈希不是加密**：`SM3(输入)==常量`→爆破；逐字节比较→截断逆推；`SM3(key\|\|msg)`→长度扩展攻击 |
| 256 位曲线参数 + 大数模运算 + 签名 | SM2 | ECC 公钥类：考点在 nonce 复用（`d=(z1-z2)/(s1-s2)`）/弱随机/曲线参数未校验，不是破曲线 |
| `0x67452301 0xEFCDAB89 0x98BADCFE 0x10325476` | MD5 | 不可逆，只能碰撞/查表；若比较"MD5(输入)==常量"则爆破或逐字节截断比较可逆推 |
| `0x6A09E667 0xBB67AE85` | SHA256 | 同上 |
| `0xEDB88320` | CRC32 | 碰撞爆破（短 flag 可行）；注意自定义初值/异或值 |
| 256字节 S盒初始化循环 + i/j 双索引 | RC4 | KSA+PRGA；注意变体：drop-N、密钥调度改、状态大小 |
| 8 字节块 + 16 轮 Feistel | DES | key 8字节；ECB/CBC |
| `0x428A2F98` | SHA-256 常量（区分用） | |
| base64 表被改 | 自定义码表 Base64 | 从代码提取码表，translate 回标准表 |
| 逐字节 XOR + 固定 key | XOR | key 长度=密文周期；已知明文首部(如"flag{")可直接推 key |
| `0x61C88647` / `0x9E3779B9` 累减 | TEA 变体(delta取反) | 注意 delta 有时是 `-0x61C88647` |
| 数据段大数组，明文搜不到 `MZ`/`PE\0\0` | **编码存储的内嵌 PE**（loader 层） | 见下节「内嵌 PE 定位」：MZ 的编码差恒为 XOR 0x17 / ADD 0x0d，可自动定位+解码 |

## 内嵌载荷定位（多阶段题第一步，工具已自动化）

> `scanCryptoFingerprints` 的载荷流水线会直接扫文件字节定位"编码存储的下一层载体"，给出**可运行提取脚本**；
> 日志出现 `[算法扫描] 载荷命中：...` 即生效。**不要**因本层搜不到明文 `MZ`/`ELF`/第二载体就断定
> "真 flag 不在此文件"——多阶段题 payload 常被编码后藏在数据段。

**覆盖的形态**（`PAYLOAD_DETECTORS` 注册表，按序尝试）：

| 形态 | 判据 | 说明 |
|---|---|---|
| 单字节 XOR/ADD × stride 1/4/2 | `buf[i]^buf[i+s]==0x17` / `(buf[i+s]-buf[i])&0xff==0x0d` | MZ 的编码差与密钥无关；stride=4 对应 `uint32_t[]` 低字节 |
| 周期 XOR（2/3/4/8 字节） | 周期 2 直接由 MZ 解出；3/4/8 用 DOS stub 已知明文恢复 | 标准 DOS stub 是常见已知明文 |
| 滚动 XOR / 滚动 ADD | `out[i]=in[i]^in[i-1]` / `in[i]+in[i-1]` | 预筛：`out[0]==0x4d` 且 `out[1]==0x17`/`0xa7` |
| Base64 / Hex 文本 | `TVqQ`/`TVo` / `4d5a` 文本 | payload 以**文本**存（不是二进制） |
| ELF / DEX | magic + 完整头校验（含 XOR/ADD 编码） | 用节头表 / `file_size` 字段推长度 |
| 裸 shellcode | `fc e8 82 00 00 00` / `fc 48 83 e4 f0` | 仅 low 置信度兜底；有真容器时不报 |

**关键护栏**（回归题集实测发现）：`key=0` 表示明文，**不能**算"内嵌载荷"——否则每个正常 ELF/PE 都会把自己
报成"内嵌自己"，让 AI 对每道正常题都先去提取下一层。偏移 0 + key 0 必须跳过。

⚠️ 第一层是 loader 时，本层通常**没有任何算法常量**（零指纹是对的）；真算法在提取出的下一层里，
**必须先把下一层提取出来再分析它**（多阶段题用 `switch_to_next_stage` 接力，不要在当前层硬啃）。
另外：第一层的校验表往往解出 **诱饵**（`This is a fake flag`）——工具已用 `isDecoyFlag` 自动识别，不会当成 ✅。

## 魔改变体识别三问（血泪教训：别把 SM4 变体猜成 AES 变体）

**先看工具扫描结果**：求解链路会在提示词顶部注入 `## ⚙️ 工具已确定性识别的算法指纹`（读文件字节扫出来的，
含 `algo / confidence / evidence / offset`）。**有 high 置信度判定时，必须先按它给的标准框架走**，
只有在标准路线全部失败（并说明报错）之后才允许进入"逐条 opcode 手撕 VM"路线。
扫描无任何指纹时，说明**本层是壳/加载器/decoy**，去下一层（内嵌 PE / 解出的 stage2）再扫。

### 工具能力速查（AI 主动调用，不等提示词喂）

| 工具 | 什么时候用 | 返回 |
|---|---|---|
| `scan_crypto(path)` | 拿到**任何**文件先调一次（含自己提取出的新文件） | 算法常量 + S 盒关系 + 内嵌载荷 + 高熵块 + 结构推理 |
| `extract_payload(path,...)` | scan 报告内嵌载荷后 | 解码写出的新文件（校验魔数） |
| `analyze_structure(path)` | scan 报"自定义分组密码"后 | 骨架假设（SM4/AES/未知）+ 置信度 + 证据 |
| `gen_sm4_solver(path)` | analyze_structure 判定 SM4 骨架后 | 可跑的全组合解密脚本 |

### 变体逆向决策树（拿到 S 盒后按此走）

```
scan_crypto 发现 256 项双射 S 盒
│
├─ S 盒关系 = 与标准表完全相同
│    → 标准算法（AES/SM4），直接用标准库解；轮数看 key 长度/代码循环
│
├─ S 盒关系 = 逐项 XOR / ADD 常量
│    → 表被整体平移。先还原标准表，再按标准算法解；
│      或直接用题目表照抄结构（两者等价）
│
├─ S 盒关系 = GF(2) 仿射（可逆矩阵）
│    → 表被线性混淆。用工具给出的 A/c 还原标准表，再按标准算法解；
│      等价做法：直接用题目表 + 标准结构
│
├─ S 盒关系 = 无任何可还原关系（全新表）
│    → 无法从标准表推导，**直接从文件读表**。轮结构看 analyze_structure：
│      · 32 项 dword 表与标准 SM4 CK 有固定差分 → SM4 骨架（用 gen_sm4_solver）
│      · Rcon 形态（10 字节 01 02 04...）→ AES 骨架（照抄结构，AI 手写实现）
│      · 8 字节块 → DES/Blowfish 方向
│      · 都不是 → 完全自定义，反编译确认轮循环后正向实现
│
└─ 结构推理给出多个假设 → 按置信度排序逐一验证，先试 high
```

### 各骨架的"魔改点清单"（变体题 90% 只改这些）

| 骨架 | 常改 | 不常改 | 验证方法 |
|---|---|---|---|
| SM4 | S 盒、FK、CK（常整体 XOR/加常量） | 轮数(32)、线性层 rol(2,10,18,24) | CK 与标准表差分是否固定 |
| AES | S 盒、Rcon、MixColumns 矩阵 | 轮函数顺序、ShiftRows 位移 | Rcon 形态是否保留 |
| DES | 8 个 S 盒、P 盒、IP/FP | 16 轮 Feistel、密钥调度 | 6→4 位 S 盒形状 |
| Blowfish | P 数组、4 个 S 盒 | 16 轮、Feistel 结构 | P 数组 18 项 + 4×256 形状 |

**常见陷阱（每一条都真实踩过）**：
- **轮密钥逆序** `rk[31-i]`：SM4 解密必须逆序，加密不用
- **块内字节反序** `[3][2][1][0]`：部分实现输出前反排 dword
- **状态反序**：标准 SM4 输出是 `(X35,X34,X33,X32)`，与轮内状态顺序相反
- **字节序**：S 盒/CK 按 dword 存（`uint32_t[]`）时值在低字节，按字节存时连续
- **密文位置**：常紧邻 key（中间隔零填充）；不要假设 16 字节对齐（Disguise 密文在 key+0x18）
- **尾部补齐**：明文按块补 `\x00`，判断可打印前先 rstrip

拿到"疑似分组密码"的判定后，**逐项回答三问**，别凭直觉猜：

1. **常量标准吗？**
   - FK `a3b1bac6 56aa3350 677d9197 b27022dc` 命中 → **确定是 SM4 家族**（AES 无此常量）。
     若 FEISTEL/轮结构也吻合，就**不要再考虑 AES**。
   - 有 FK 但 S 盒首字节 ≠ `D6` → **SM4 魔改变体**（FK/CK 标准、S 盒被替换）。
2. **S 盒是双射吗？**
   - 256 字节表且 0..255 每字节恰出现一次 → 是一个**合法分组密码 S 盒**（`T-table`/`S-box`）。
   - 首字节 `63` → AES 标准；`d6` → SM4 标准；`52` → AES 逆 S 盒；**其它值 = 自定义**（但结构可能仍是 SM4/AES 的）。
   - ⚠️ **S 盒未必是连续 256 字节**：C 里 `unsigned int sbox[256]` 占 **4 字节/项**，文件里是
     `8e 00 00 00  2f 00 00 00 …`（值在低字节）。找 S 盒**必须 stride=1/2/4 都试**，
     只扫连续字节会完全漏掉它（Disguise 的自定义 S 盒 @0xd630 即此形态）。
   - ⚠️ 双射 ≠ S 盒：偏移/跳转表、位重排表、GF(2⁸) 反对数表也是双射。判据：相邻差分布的
     种类数（真实 S 盒 ≥160，误报表 6~8）。
3. **轮结构是什么？**
   - 32 轮 + `X^X^X^rk` 线性变换 L（循环移位 2/10/18/24）→ SM4 特征。
   - SubBytes/ShiftRows/MixColumns/AddRoundKey 四步 → AES 特征。
   - 16 轮 Feistel + 初始/逆初始置换 → DES。

**魔改变体的正确处理**（以 Disguise 的 SM4 变体为例）：
结构照抄标准 32 轮，只把**常量表换成题目里的**——FK/CK/S 盒全部用题目内存中的那张表。
`gmssl` 等标准库**必然解出乱码**（它内置标准 S 盒），此时不要怀疑思路，而要**按结构手写 32 轮**。
解密额外注意：轮密钥逆序 `rk[31-i]`、块内最后字节反序 `[3][2][1][0]`（具体以题目代码为准）。

## 还原策略（按信息量）

1. **算法+密钥+密文齐全** → 直接写解密脚本，输出 `[VERIFY]` 供工具复现
2. **算法知道，密钥未知但运行时可取** → 输出 Frida Hook 方案，动态拿 key
3. **自定义算法** → 逐轮还原：先看输入输出长度，再逆数据流；复杂轮函数用 Z3 约束求解（约束=比较逻辑）
4. **哈希比较** → 判断可否截断比较逐字节爆破；否则字典/规则爆破（rockyou + 变形规则）

## 字节序陷阱

- TEA 系列在 C 里常用 `uint32_t` 直接操作 → x86 小端；Python 用 `struct.pack('<I')` 还是 `'>I'` 必须与原实现一致
- AES 的 state matrix 列优先 vs 行优先
- 密钥 "1234567812345678" 是 ASCII 16 字节 ≠ hex 解码的 8 字节——分清 `key.encode()` 与 `bytes.fromhex(key)`

## 输出契约

识别完成后输出（供工具本地枚举）：
```
[HYPOTHESES][
 {"algo":"tea","key":"<hex或ascii>","ciphertext":"<hex>","encoding":"hex","variant":"le32"},
 {"algo":"xxtea","key":"...","ciphertext":"...","encoding":"hex","variant":"be32"}
][/HYPOTHESES]
```
支持 algo：tea/xtea/xxtea/rc4/xor/aes_ecb/aes_cbc/des_ecb/des_cbc/des3_ecb/sm4_ecb/sm4_cbc/sm3/chacha20/salsa20/base64/base64_custom/custom。
国密提示：SM4 先试 `sm4_ecb` 再试 `sm4_cbc`（附 `iv`+`iv_encoding`）；S 盒被改的变体 gmssl 解不出，需按 32 轮手写。
SM3 是哈希（不可逆），`algo:"sm3"` 仅用于"SM3(候选)==目标"的对比，不产出明文。
完整国密方法（SM2/SM3/SM4 分型与打法）见知识库 `wiki/reverse/method_gm_crypto.md`。
注意：crc32 碰撞不适合放进 HYPOTHESES（自动求解窗口 30 秒跑不完），按需单独给完整碰撞脚本；custom 需附 `code` 字段（完整 Python `def decrypt(data,key)`）。
