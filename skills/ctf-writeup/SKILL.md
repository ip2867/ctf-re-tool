# CTF 题解（Writeup）写作规范

为本工具生成**提交级**题解。目标：队友或出题方照着 WP 能在 5 分钟内复现解题。

## 核心原则

1. **一条完整脚本**：解法代码必须是"从题目原始数据 → 打印最终 flag"的**单一可运行脚本**（含全部 import、常量、密钥、密文）。不要把"取密钥/推导/解密"拆成多个零散片段。
   - VM/字节码题的脚本必须三段齐全：**常量数据表（原始字节或解码后数组）+ 按 case 复刻的模拟器 + 逐位反解**；只有伪代码思路不算完整脚本。
2. **可复现**：每一步的输入输出来自真实运行结果（引用 `cases/<题目>/evidence/` 下的证据或 findings.json），不用"大概/应该是"。
3. **诚实标注**：flag 与关键结论必须区分 `✅已验证`（本地复现通过）与 `⚠️AI推断`（未复现）。
4. **精简**：1-3 个步骤讲完；不写长篇背景；死胡同只在"它解释了关键转折"时才提；多种解法只写最干净的一种。

## 完稿检查清单

- [ ] 元数据齐全（题目名/分类/难度/flag 格式/工具）
- [ ] 摘要 ≤2 句
- [ ] 求解脚本从原始数据直达 flag，复制即可运行
- [ ] 每个关键结论都有证据出处（函数地址/寄存器值/输出快照）
- [ ] Flag 标注了验证状态
- [ ] 地址、密钥、密文与动态调试实测一致，不是猜测值
- [ ] VM 题脚本含常量表+模拟器+反解三段，校验值按无符号字节对齐（有符号 int8 需 &0xff）
- [ ] 无敏感信息（真实凭据/API Key）

## 本工具上下文

- 证据在 `cases/<题目>/` ：`findings.json`（结构化发现）、`evidence/`（MCP 抓取的函数表/字符串/反编译）、`timeline.jsonl`（操作时间线）
- 已验证的 flag 在 findings.json 的 flags 数组中 `verified: true`
- 生成后写入脚本预览区（Markdown 类型），自动保存到 case 目录
